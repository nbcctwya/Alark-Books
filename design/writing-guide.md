# 写作与素材规范

在 Obsidian 中打开整个 `vault`，每本书放入 `books/<书籍目录>/`。书中内容尽量使用普通 Markdown，这样可以独立于编辑器长期保存。

## 章节

```markdown
---
subtitle: 用一句话说明读者将获得什么。
---
# 本章标题

正文从这里开始。

## 小节标题

一个段落发展一个主要观点。
```

每章以一个一级标题开始。导出器用它生成章节首页，并从正文中去掉这一次重复标题。可在 YAML 中用 `title` 覆盖标题，`subtitle` 作为引导语。二、三级标题用于组织正文，不要跳跃使用标题层级来模拟字号。

不要在 Markdown 中手工重复封面、目录、页码；这些由模板生成。章节顺序以 `book.yml` 的 `chapters` 为准。

## 图片与图表

素材放在 `vault/assets/<书名>/` 中，文件名有意义且尽量唯一。以下两种语法均可：

```markdown
![[assets/my-book/workflow.png|图 2-1　内容工作流程。来源：作者绘制。]]

![图 2-1　内容工作流程。来源：作者绘制。](../../assets/my-book/workflow.png)
```

独占段落的图片会转成图与图注。图注使用替代文字，不再需要在下一行重复写。Obsidian 的 `![[图片.png|360]]` 可以限制宽度；若要完整图注，优先使用文字标签。支持 PNG、JPEG、GIF、WebP 与 SVG；EPUB 中 WebP 会转换为 PNG 以兼容更多阅读器。

照片保留足够像素，数字图表尽量使用 SVG 或高分辨率 PNG。以 150 mm 宽、300 DPI 落版，图片宽度约需 1772 像素。图表中的文字应按最终尺寸阅读，避免只看原图时显得清楚。为图表注明单位、统计口径、来源、日期；虚构样例明确标为测试数据。

多张图片请分别放在不同段落。竖长图会缩小并限制高度，极长网页截图建议拆成几个有意义的局部。不要通过图片嵌入整页正文。

## 链接

```markdown
[[02-system|下一章]]
[[02-system#把流程写成接口|工作接口]]
[下一章](02-system.md)
[同章小节](#小节标题)
[公开来源](https://example.com/article)
```

导出器为 PDF、HTML、EPUB 分别生成正确的内部链接。目标章节必须列入本书，错链或缺失标题会中止导出，防止出版后留下失效的 Obsidian 跳转。暂不支持跨书链接、Obsidian 块锚点、未收录笔记的链接，以及 `![[笔记.md]]` 内容嵌入。

代码块和行内代码中的 `[[文字]]` 保持原样。重名文件会提示使用明确路径。

## 提示、引用、脚注

```markdown
> [!tip] 本章行动
> 给读者一个可以执行的小步骤。

> [!note] 旁注
> 写明方法的背景或适用边界。

> [!warning] 注意
> 指出会影响结果的具体条件。

> 一段值得停下来阅读的话。

一个带来源的判断。[^source]

[^source]: 作者、标题、日期与公开链接。
```

提示块支持多段内容、强调和列表。折叠标记 `[!note]+`、`[!note]-` 导出时展开。脚注导出为章末注，编号按章节独立，EPUB 支持点击往返。注释应该在本章内定义。

## 表格和代码

普通 Markdown 表格支持自动换行、白底细线、重复表头。表格第一列名为“记录”“编号”“序号”时自动收窄，给内容列更多空间。尽量不超过四到五列；没有意义的宽表不适合用缩小文字解决。

代码围栏可注明语言，但目前不提供语法着色。代码会换行，短代码块尽量保持完整。原始 HTML 作为文字显示，不直接执行。`%% ... %%` 为编辑备注，导出时去除。

## 发布前最后一遍

检查目录顺序与标题；确认所有数字、图注和来源；逐页看 PDF 的图文间距和分页；在目标 EPUB 阅读器调整一次字号；最后确认版本号、作者署名和封面。每次重要修改后重新构建，旧导出文件不会自动随 Obsidian 编辑变化。

## 摄影封面

可在 `book.yml` 指定 `cover_image`、`cover_alt`、`cover_credit`，图片放在 `vault/assets`，支持 PNG / JPEG。没有封面图时生成纯字体封面。详见 [纸本方向说明](editorial-direction.md)。
